# SZPI-OS 产品需求文档

## 1. 产品概述

SZPI-OS 是运行在立创·实战派 ESP32-S3 开发板上的嵌入式操作系统固件。

## 2. 功能需求

### 2.1 系统与内核

#### SYS-001 启动序列

- 输入：上电 / 复位信号
- 输出：完整启动流程（驱动初始化 → 外设初始化 → 服务初始化 → 框架初始化 → 注册 App → 开机画面 → 进入桌面）
- 行为：按预定顺序初始化各层；内置 Flash 在首屏之后挂载，看门狗在启动完成后才打开超时自动重启
- 边界：关键层初始化失败则中止启动并记录日志
- 优先级：P0
- 依赖：无
- 验收标准：
  - 上电后 5 秒内显示桌面
  - 启动失败有日志记录

#### SYS-002 多任务调度

- 输入：FreeRTOS 内核
- 输出：多任务并行执行
- 行为：基于 FreeRTOS 的任务调度，每个服务独占任务
- 优先级：P0
- 依赖：ESP-IDF FreeRTOS
- 验收标准：任务 CPU 占用可查询

#### SYS-003 看门狗

- 输入：系统异常 / 任务挂起
- 输出：超时自动重启系统
- 行为：Task Watchdog 监控关键任务；启动完成前只告警，启动完成后打开自动重启
- 边界：超时阈值默认 5 秒，可配
- 优先级：P0
- 依赖：SYS-002
- 验收标准：关键任务挂起超过阈值后系统自动重启

#### SYS-004 异常处理与 crash log

- 输入：系统异常 / 断言失败
- 输出：崩溃现场写入保留内存，重启后写入 NVS 并打印
- 行为：包装 panic handler，记录任务名 / 调用栈 / 运行时长；只保留最近若干条
- 边界：无 coredump 分区；cache 关闭时崩溃只保留复位原因
- 优先级：P1
- 依赖：SYS-002
- 验收标准：触发崩溃重启后，串口可读到崩溃信息

#### SYS-005 系统信息查询

- 输入：API 调用
- 输出：CPU / 内存 / Flash 使用情况、复位原因、运行时长
- 行为：统一 API 返回运行时信息
- 边界：API 内部加锁，并发安全
- 优先级：P1
- 依赖：SYS-002
- 验收标准：返回值与实际状态一致

#### SYS-006 软复位 / 硬复位

- 输入：API 调用 / 复位键（EN）
- 输出：系统重新启动
- 行为：软复位保留 NVS 数据；硬复位由 EN 键触发
- 边界：复位丢失运行时内存数据
- 优先级：P0
- 依赖：无
- 验收标准：调用软复位 API 后系统重启；按 EN 键触发硬复位

#### SYS-007 电源管理（关机 / 重启）

- 输入：用户请求
- 输出：关机 / 重启
- 行为：提供关机与重启接口；重启走软复位
- 边界：关机不切断 Type-C 供电
- 优先级：P0
- 依赖：SYS-006
- 验收标准：关机 / 重启入口生效

#### SYS-008 时间管理

- 输入：SNTP 同步 / 手动设置
- 输出：本地时间（年 / 月 / 日 / 时 / 分 / 秒 / 时区）
- 行为：维护系统时间戳；支持时区设置与 12 / 24 小时制；联网后自动同步，并每 6 小时定时重新同步；未联网时可手动校时（精确到秒）
- 边界：12 / 24 小时制存在 NVS（`sys/clock_24h`），状态栏与时钟 App 共用同一个设置；本板无电池 RTC，时间靠两层保住 —— RTC 保留内存（软复位，误差 < 1 秒）+ NVS（`sys/time_epoch`，掉电也不丢，每分钟与校时后写一次，拔电重启后误差 ≤ 1 分钟），开机取两者中较晚且有效的值
- 优先级：P0
- 依赖：无
- 验收标准：联网后时间自动同步；设置后时钟 App 与状态栏显示一致且正确；热重启与拔电重启后时间（含日期）都不回到 1970

#### SYS-009 屏幕超时熄屏 / 唤醒

- 输入：无操作时间累计 / 触摸 / 按键 / 抬手
- 输出：屏幕熄灭 / 点亮
- 行为：默认 30 秒无操作熄屏（只关背光，LCD 保持）；触摸 / 按键 / 抬手唤醒
- 边界：熄屏 ≠ 关机
- 优先级：P1
- 依赖：SYS-007
- 验收标准：超时后熄屏；触摸 / 按键 / 抬手点亮

#### SYS-010 亮度调节

- 输入：UI 滑块 / 控制接口
- 输出：LCD 背光 0-100%
- 行为：调节背光亮度并持久化到 NVS
- 边界：亮度 0 表示关闭背光
- 优先级：P0
- 依赖：无
- 验收标准：调节实时生效，重启后保持

#### SYS-011 音量调节

- 输入：UI 滑块 / 控制接口
- 输出：音频输出音量 0-100%
- 行为：实时调节 codec 音量并持久化
- 优先级：P0
- 依赖：无
- 验收标准：调节实时生效

### 2.2 脚本系统

#### SCR-001 脚本运行时

- 输入：Lua 脚本
- 输出：脚本执行
- 行为：内置 Lua 5.5 运行时，提供加载、执行、停止接口
- 边界：运行内存受内部 RAM / PSRAM 限制
- 优先级：P0
- 依赖：无
- 验收标准：能加载并执行示例脚本

#### SCR-002 脚本列表与元信息

- 输入：TF 卡与内置存储
- 输出：脚本列表（名称 / 说明 / 入口）
- 行为：递归扫描两个存储的整盘目录树，收录所有 `.lua`（扩展名不分大小写），读取每个脚本的元信息，供脚本管理展示；`scripts` 目录只是官方推荐位置，脚本放别处一样能扫到
- 边界：无元信息的脚本以文件名作为名称；目录层级与路径长度有上限，超出的跳过
- 优先级：P0
- 依赖：STO-001
- 验收标准：脚本管理列出两个存储里的所有脚本

#### SCR-003 脚本生命周期管理

- 输入：运行 / 停止请求
- 输出：脚本启动 / 停止 / 异常退出
- 行为：同一时刻只运行一个前台脚本；**每个运行中的脚本都有自己的页面** —— 调了 `ui.page()` 的显示脚本界面，没调的显示「运行日志」页（脚本 `print` 的输出）；离开这个页面即停止脚本，脚本也可以自己调 `sys.exit()` 结束；退出或异常时释放资源并回到脚本管理
- 边界：脚本异常退出不影响系统
- 优先级：P0
- 依赖：SCR-001
- 验收标准：运行中可停止；异常退出后系统正常

#### SCR-004 脚本错误处理与日志

- 输入：脚本语法 / 运行错误
- 输出：错误信息（行号 + 描述）
- 行为：捕获 Lua 错误，写日志并在界面提示
- 优先级：P1
- 依赖：SCR-001
- 验收标准：错误脚本给出明确报错，不崩溃

#### SCR-005 脚本配置持久化

- 输入：脚本读写配置
- 输出：配置保存到 NVS 或文件
- 行为：脚本通过 API 持久化自己的配置
- 优先级：P1
- 依赖：SCR-001、STO-007
- 验收标准：脚本配置跨重启保留

#### SCR-006 脚本权限与沙箱

- 输入：脚本头部的能力声明
- 输出：脚本内可用的能力模块
- 行为：脚本头部用 `-- @perm io,file,net` 声明要用的能力模块；不写声明表示全部模块可用；写了声明就只注册列出的模块，未声明的模块在脚本里为 nil，调用即报 Lua 错
- 边界：ESP32-S3 无 MMU，为软件级限制
- 优先级：P2
- 依赖：SCR-001
- 验收标准：脚本声明限制后，调用未声明的模块报 Lua 错

#### SCR-007 内置示例脚本

- 输入：固件内置脚本
- 输出：每次启动释放到脚本目录
- 行为：随固件打包若干示例脚本，供用户选择运行
- 边界：同名脚本已存在时覆盖为固件内置版本
- 优先级：P1
- 依赖：STO-001
- 验收标准：启动后脚本目录有固件内置的示例脚本

#### SCR-008 网络脚本下载

- 输入：脚本 URL
- 输出：脚本保存到脚本目录
- 行为：在「下载」App 里输入 `.lua` 链接，经 HTTP / HTTPS 下载到脚本目录（脚本管理 App 不再自带下载入口）
- 边界：下载失败不残留半截文件
- 优先级：P1
- 依赖：NET-005、STO-001
- 验收标准：输入链接后脚本出现在脚本管理列表里并可运行

### 2.3 脚本能力

#### CAP-001 显示与界面

- 输入：脚本调用界面接口
- 输出：LVGL 控件 / 页面 / 图片 / 画布
- 行为：脚本可创建页面与控件，显示文字 / 图片 / 进度 / Toast，或用画布自己画像素（指针时钟、小游戏）
- 边界：界面操作在 LVGL 任务上下文执行
- 优先级：P0
- 依赖：SCR-001、UI-006
- 验收标准：脚本能绘制并刷新界面

#### CAP-002 输入

- 输入：触摸 / 姿态 / 按键
- 输出：脚本回调
- 行为：脚本可注册触摸、姿态、按键事件
- 优先级：P0
- 依赖：SCR-001、IN-001 / IN-002 / IN-003
- 验收标准：点击屏幕脚本收到事件

#### CAP-003 音频播放 / 录音

- 输入：脚本调用音频接口
- 输出：播放 / 录音
- 行为：脚本可播放音频文件与提示音、启动 / 停止录音
- 优先级：P1
- 依赖：SCR-001、MM-001 / MM-002
- 验收标准：脚本能播放音频

#### CAP-004 摄像头拍照

- 输入：脚本调用摄像头接口
- 输出：拍照文件
- 行为：脚本可开关摄像头并拍照，照片保存到 TF 卡
- 优先级：P1
- 依赖：SCR-001、MM-004
- 验收标准：脚本能拍照并在 TF 卡生成照片文件

#### CAP-005 GPIO / PWM / I2C / UART / ADC / CAN

- 输入：脚本调用硬件接口
- 输出：外设操作
- 行为：脚本可控制 GPIO、输出 PWM、收发 I2C / UART 与 CAN、读取 ADC
- 边界：仅限外扩接口引出的 GPIO10 / GPIO11 与可用外设；UART 与 CAN 各占两个引脚，需外接收发器
- 优先级：P1
- 依赖：SCR-001
- 验收标准：脚本能点亮外接 LED、读写外接 I2C 器件

#### CAP-006 文件读写

- 输入：脚本调用文件接口
- 输出：TF 卡 / 内置 Flash 读写
- 行为：脚本可读写、删除、列目录
- 优先级：P0
- 依赖：SCR-001、STO-003
- 验收标准：脚本能保存并读回文件

#### CAP-007 网络

- 输入：脚本调用网络接口
- 输出：HTTP / HTTPS / MQTT / WebSocket
- 行为：脚本可发 HTTP(S) 请求、连接 MQTT / WebSocket
- 优先级：P1
- 依赖：SCR-001、NET-005 ~ NET-008
- 验收标准：脚本能获取网页内容

#### CAP-008 蓝牙 BLE

- 输入：脚本调用 BLE 接口
- 输出：广播状态 / 连接状态 / 通知
- 行为：脚本可开关广播、扫描周边设备、查询连接状态，并作为 GATT 从机响应中心设备的特征读写、发送通知；也可作为中心设备连接扫描到的外设，发现它的服务、读写特征并订阅通知
- 优先级：P1
- 依赖：SCR-001、NET-002
- 验收标准：脚本能开关广播、发送通知；手机能搜索并连接板子

#### CAP-009 时间与系统信息

- 输入：脚本调用
- 输出：时间、内存、运行时长等
- 行为：脚本可读取系统时间、内存与运行时长
- 优先级：P0
- 依赖：SCR-001、SYS-005 / SYS-008
- 验收标准：脚本能读到正确时间与内存

#### CAP-010 事件订阅与发布

- 输入：脚本订阅 / 发布事件
- 输出：事件回调
- 行为：脚本可订阅系统事件，也可发布自定义事件
- 优先级：P0
- 依赖：SCR-001
- 验收标准：脚本收到系统事件回调

#### CAP-011 系统通知（Toast）

- 输入：脚本调用通知接口
- 输出：界面 Toast
- 行为：脚本可弹出 Toast 提示
- 优先级：P1
- 依赖：SCR-001、UI-006
- 验收标准：脚本能弹出 Toast

#### CAP-012 网页服务（局域网）

- 输入：脚本注册路由与处理函数
- 输出：局域网浏览器可访问的网页
- 行为：脚本用 `web.get` / `web.post` 注册路由（挂在设备 Web 控制台的 `/s` 前缀下），处理函数收到方法 / 路径 / query 表 / 请求体，返回内容类型与响应体（也可带状态码）；`web.url()` 给出访问地址。路由只在脚本运行期间有效，脚本停止即失效；响应体上限 24 KB
- 边界：需要设备已连上 Wi-Fi（Web 控制台在监听）；不做认证，只在可信局域网内使用；处理函数要尽快返回，否则会拖住整个 Web 控制台
- 优先级：P2
- 依赖：NET-010、SCR-001、CAP-001
- 验收标准：运行内置的 `gomoku.lua`，局域网电脑 / 手机浏览器打开提示的地址能正常下五子棋，设备屏幕上同步显示棋盘

### 2.4 UI 系统

#### UI-001 主题系统

- 输入：用户设置 / 系统默认
- 输出：深色 / 浅色主题
- 行为：调色板统一走主题接口，控件显式设色
- 边界：仅深色 / 浅色二选一
- 优先级：P0
- 依赖：无
- 验收标准：默认深色；两种主题下控件均可见

#### UI-002 主题运行时切换

- 输入：用户切换主题
- 输出：全局立即刷新
- 行为：切换后重建状态栏、浮层与所有界面
- 优先级：P1
- 依赖：UI-001
- 验收标准：切换后立即生效，无需重启

#### UI-003 字体系统

- 输入：字体名称 / 字号
- 输出：渲染对应字体文字
- 行为：中文字体内置两套界面字体（GB2312 全集，14 / 16 px），另有 GBK 全集回退字体；拉丁 / 数字用内置 Montserrat
- 边界：界面文案的汉字必须在字体覆盖范围内（ASCII ∪ GBK）
- 优先级：P0
- 依赖：无
- 验收标准：所有界面文字渲染正确，无缺字

#### UI-004 图片资源系统

- 输入：图片路径
- 输出：图片渲染到屏幕
- 行为：内置图片编译进固件，TF 卡图片运行时读取
- 边界：支持 PNG / JPEG / GIF / BMP
- 优先级：P0
- 依赖：STO-001
- 验收标准：内置与 TF 卡图片均能正确显示

#### UI-005 图标系统

- 输入：图标标识
- 输出：图标渲染
- 行为：每个 App 一个自绘彩色图标，集中由图标生成脚本产出
- 边界：图标尺寸固定
- 优先级：P0
- 依赖：UI-004
- 验收标准：桌面图标清晰显示

#### UI-006 通用 UI 组件

- 输入：组件类型 + 参数
- 输出：进度条 / 对话框 / Toast / 列表 / 网格
- 行为：基于 LVGL 封装统一接口
- 优先级：P0
- 依赖：UI-001、UI-003
- 验收标准：组件在所有界面风格一致

#### UI-007 状态栏

- 输入：时间 / Wi-Fi / 蓝牙 BLE / 声音 / 录音 / 摄像头 / TF 卡状态
- 输出：屏幕顶部状态栏
- 行为：左侧为返回与主页按钮；右侧 6 个状态图标全部常显、不可点击，启用 / 触发时用主色高亮，否则置灰
  - Wi-Fi：连上 AP 时高亮（未连接 / 连接中 / 失败都置灰）
  - 蓝牙 BLE：广播中、或从机 / 中心任一链路已连接时高亮（都没连才置灰）
  - 声音：扬声器放音时高亮
  - 录音：麦克风录音时高亮
  - 摄像头：摄像头打开时高亮
  - TF 卡：卡可用（已挂载且仍能访问）时高亮
- 边界：状态栏高度固定；图标亮灭由各服务事件驱动实时响应，另有 1 s 兜底同步
- 优先级：P0
- 依赖：UI-001、SYS-008、NET-001
- 验收标准：各图标严格跟随上表对应状态的亮灭，不出现残留高亮

#### UI-008 桌面

- 输入：系统启动 / 主页键
- 输出：应用图标网格 + 状态栏
- 行为：一屏固定 4×2，超出可左右滑动翻页（底部页码点，lv_tileview）；每个格子为彩色图标 + 中文名称，点击图标启动 App
- 边界：桌面是返回栈的栈底
- 优先级：P0
- 依赖：UI-005、UI-007
- 验收标准：上电后桌面正常显示，图标可点击

### 2.5 输入系统

#### IN-001 触摸输入

- 输入：FT6336 触摸事件
- 输出：触摸坐标与点击 / 长按事件
- 行为：扫描任务轮询读取坐标并缓存，LVGL 输入设备只读缓存
- 边界：单点触摸，不支持多指手势
- 优先级：P0
- 依赖：无
- 验收标准：点击 / 长按定位准确

#### IN-002 IMU 姿态输入

- 输入：QMI8658 加速度 / 陀螺仪数据
- 输出：姿态变化 / 摇晃 / 抬手事件

- 优先级：P1
- 依赖：SNS-001
- 验收标准：晃动板子能触发摇晃事件

#### IN-003 物理按键输入

- 输入：BOOT 键 GPIO0
- 输出：单击 / 双击 / 长按事件
- 行为：轮询 + 软件去抖判定；单击返回上一级、双击回到桌面、长按弹出电源菜单（按住期间到点即弹出，不需松手）
- 边界：仅 1 个用户按键
- 优先级：P0
- 依赖：无
- 验收标准：单击 / 双击 / 长按准确识别

#### IN-004 输入防抖

- 输入：触摸 / 按键事件流
- 输出：去抖后的事件
- 行为：按键按 10 ms 采样、连续 30 ms 电平稳定才认可一次；触摸由扫描任务缓存坐标并做点击 / 长按判定
- 边界：可能漏掉极快的连击
- 优先级：P1
- 依赖：IN-001 / IN-003
- 验收标准：连续抖动只触发一次事件

- 输入：同一局域网里的电脑 / 手机浏览器

- 行为：设备连上 Wi-Fi 拿到 IP 后自动在 80 端口提供 HTTP 服务，断开即停；浏览器打开 `http://<设备 IP>/` 后：**系统状态**页显示系统信息（芯片 / 版本 / MAC / 运行时长 / 复位原因 / 内存）、Wi-Fi 连接信息（状态 / SSID / IP / 信号）、蓝牙连接信息（状态 / 广播 / 已连接设备）与最近系统日志（自动刷新，可暂停 / 过滤），页面上有「刷新」按钮立即重取；**文件管理**页浏览 TF 卡与内置存储的完整目录树，支持上传（含多选与拖拽，带进度）、下载、多选批量删除、重命名、新建文件夹、删除目录（含内容），以及复制 / 剪切 / 粘贴（重名自动加序号），工具栏有「刷新」重读当前目录；复制 / 剪切 / 删除在设备上以后台任务执行并显示进度，界面不会卡住。Wi-Fi App 里显示访问地址

- 优先级：P1
- 依赖：NET-001、STO-001、SYS-005、SYS-006
- 验收标准：连上 Wi-Fi 后电脑浏览器打开设备 IP 即可看到两个页签；状态页数据与实际一致并自动刷新；文件页能上传 / 下载 / 多选删除 / 重命名 / 新建文件夹 / 复制剪切粘贴，操作结果与「文件管理」App 一致

- 优先级：P0
- 依赖：SYS-008、NET-004、UI-003

#### APP-CALENDAR 日历

- 输入：系统时间 / 用户操作（切年 / 切月 / 长按某天）
- 输出：单屏月视图（一行头部 + 7 列网格，表头 + 固定 6 周）
- 行为：默认显示当月并高亮当天（强调色圆角底）；周末用辅色（含星期表头的「日 / 六」，比工作日文字更醒目）、相邻月份的日期置灰；`《` / `》` 切年、`◀` / `▶` 切月、「今天」跳回当月；**长按本月的某一天 → 对话框「把 X 年 X 月 X 日设为今天？」**，确认后只改年月日、保留当前时分秒（改完即视为时间可信，联网后由 SNTP 再校准）；每分钟检查一次今天是否变化（跨零点 / 改时区 / 手动改日期）
- 边界：仅查看，不记事；年份限制 1970 ~ 2099；时间未同步时不高亮今天、也不额外提示（长按某天即可把日期设过来）
- 优先级：P1
- 依赖：SYS-008、UI-003
- 验收标准：显示正确的月历与日期；今天只有一个且随日期变化移动；长按任意本月的日期能把系统日期设成那天；切年 / 切月 / 今天都即时生效

#### APP-WEATHER 天气

- 输入：天气接口（Open-Meteo，免 key）/ 用户选择城市
- 输出：单屏（头部 + 实况卡 + 详情表）。头部：天气图标（无数据时是置灰的太阳；有数据后按天气换成晴 / 云 / 雨 / 雪 / 雾 / 雷，夜间晴天用月亮，统一用辅色高亮）+ 状态 / 错误提示（平时为空）+「选择城市」（图标 + 城市名）+ 刷新；实况卡：温度（24 px）+ 天气状况（强调色）+ 今日高低温 / 日出日落；详情表 3 列 × 3 行（体感 / 湿度 / 风 / 云量 / 气压 / 降水量 / 降水概率 / 阵风 / 更新），行列为 1 px 表格线、格内标题靠左数值靠右两端对齐。没有数据时类目全部渲染、数值显示 `--`，温度写「无数据」

- 边界：需要可访问的天气接口（未联网时提示「请先连接 Wi-Fi」）；LVGL 键盘没有中文 IME，城市名只能输拼音 / 英文，所以提供常用城市快捷选；同一时刻只发一个请求
- 优先级：P2
- 依赖：NET-005
- 验收标准：联网后显示当前天气；换城市后立即刷新；断网时给出明确提示

- 行为：进 App 自动扫描一次，之后点右上角扫描；点列表里的网络即连接（开放网络直连，加密网络弹密码浮层，浮层内有"显示密码"选框，键盘回车即提交）；连接状态由事件驱动即时刷新，当前连接的网络在列表里用强调色标出；断开后可"重连"（用已保存的凭据，不需要再输密码）；提供 AP 网页配网与 SmartConfig 两种配网方式，**两者都只在未连接状态下才能开启**（已连接时点按提示"已连接网络，请先断开"），开启配网热点后提示里给出热点名称与 192.168.4.1；忘记网络带二次确认

- 验收标准：能扫描到周边网络并连接指定 AP，显示 SSID 与 IP；断开后重连不需要密码；忘记网络后凭据确实被清除

#### APP-BT 蓝牙 BLE

- 输入：用户操作 / 按键 / 触摸
- 输出：主页按角色分两个标签（**从机·被连接**：协议栈状态 + 广播开关 + 键鼠入口；**主机·主动连**：中心链路状态（带对端名字）+ 扫描 + 周边设备列表）+ 子页：键鼠页（4 列 × 4 行网格：方向键 / 键盘常用（Esc、Tab、退格、空格、回车）/ 鼠标点击（左、中、右）/ 鼠标移动（上下左右））；GATT 页（对端服务列表 ←→ 特征列表，点特征读值，头部按钮对选中特征读 / 订阅）
- 行为：从机标签显示中文状态（未启动 / 就绪 / 广播中 / 已连接 <设备名>）并开关广播（已连接时同一按钮变成断开），配对完成后键鼠入口才点亮可用；主机标签显示中心链路状态（未连接 / 连接中 / 已连接 <设备名>），进 App 自动扫描一次，之后点扫描按钮（列表里没广播名字的设备用蓝牙地址显示；扫描结束提示发现数量）；点设备连接它（已连接时再点一次断开，点别的设备先断开再连），连上后**自动发起配对 / 加密**并发现服务、进 GATT 页（要求加密的对端不会再把我们踢掉）；配对后作为 HID 键盘 / 鼠标上报按键、鼠标点击与鼠标移动；返回键在 GATT 页按"特征列表 → 服务列表 → 主页"逐级退回
- 边界：HID 上报需先完成配对连接，未就绪只提示不发送；从机（HID）角色的配对用「安全连接 + MITM + 绑定」，两端比对同一串 6 位码、或输入对端显示的 6 位码（提示由框架全局弹出，离开 App 也能配对）；中心角色只用「安全连接 + 绑定」（不要求 MITM，否则不支持它的设备会配对失败并被协议栈断链），且只对**已绑定过**的对端主动重新加密，新设备等对端发起配对；中心连接与从机链路互不影响，离开 App 不断开（主机链路要断开就再点一次那台设备，从机链路用从机标签的断开按钮）；作为从机被连接时广播自动暂停
- 优先级：P1
- 依赖：NET-002、NET-009
- 验收标准：进 App 能自动扫到设备（含未命名设备的地址）并在结束时给出数量；点设备能连上并列出对端服务；点特征能读到值，订阅后能收到通知；作为键盘连手机能输入文字；鼠标点击与移动生效

## 3. 非功能需求

### 3.1 性能

- 启动时间：上电到桌面 < 5 秒
- UI 帧率：动画 / 界面刷新 ≥ 30 FPS
- 触摸响应延迟：< 100 ms
- Wi-Fi 连接时间（已知 SSID）：< 5 秒
- 脚本启动延迟：< 500 ms
- 音乐启动延迟：< 300 ms

### 3.2 可靠性

- 连续运行（不重启）：≥ 72 小时
- 看门狗：关键任务全部纳入监控
- 崩溃日志：保留最近若干次
- 脚本异常：不拖垮系统

### 3.3 兼容性

- 硬件：立创·实战派 ESP32-S3（N16R8）
- 工具链：ESP-IDF v6.1
- 编译器：GCC（xtensa-esp32s3-elf-gcc）
- 文件系统：FAT32（TF 卡）+ SPIFFS（内置 Flash）

### 3.4 可维护性

- 代码组织：5 层分层（Drivers / Peripherals / Services / Framework / Apps）

- 编码风格：遵循项目既有命名与日志约定

## 4. 范围与非范围

- Wi-Fi 配网与管理、BLE 连接与管理（含 HID 模拟）、时间同步

- 多用户 / 应用商店
- 通话 / 短信 / GPS / NFC
- AI 语音助手

## 5. 验收标准

### 5.1 完成定义

满足以下全部条件视为完成：

1. 编译通过：`idf.py build` 无错误
2. 烧录成功：可烧录到实战派 ESP32-S3 并启动
3. 开机启动：上电后 5 秒内显示桌面
4. UI 流畅：触摸 / 界面刷新 ≥ 30 FPS
5. 脚本可用：能运行内置示例脚本，脚本能操作界面与硬件
6. 范围中的内置应用均可正常打开和使用
7. 状态持久化：所有用户设置跨重启保留
